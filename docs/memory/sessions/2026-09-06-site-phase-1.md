## Context

V2 Phase 1 (Design System & Core Shell) exit criteria: components are reusable
and a complete page can be assembled without custom styling from scratch.
`apps/web` was a single 1000-line client page with inline header/footer, no
mobile nav, no reusable components, and unhardened `next.config.ts`.

## Record

New in `apps/web/src`:

- `data/site.ts`: services, process steps, primary/footer nav, slug helpers,
  `INQUIRY_EVENT` shell-to-page contract.
- `data/site.test.ts`: 9 passing `node:test` assertions (slug resolution,
  data invariants, nav anchors).
- `components/`: `brand`, `button` (primary/secondary/gold-ghost/ghost, link or
  button), `section-header` (split/stacked), `service-card`, `process-steps`,
  `faq` (native details, no JS), `cta-section`, `form-field`
  (input/textarea/select), `status-message`, `site-header` (mobile nav, Escape
  to close, dispatches inquiry event), `site-footer`.
- `app/layout.tsx`: renders shell header/footer plus skip link.
- `app/page.tsx`: homepage rewired onto the system; header/footer removed from
  the page; hero, services, process, about CTA, and inquiry form consume the
  new primitives with unchanged visuals and behavior.
- `next.config.ts`: `poweredByHeader: false`, compression, security headers
  (mirrors `apps/team`).
- `app/not-found.tsx`, `app/error.tsx`: shell-styled 404 and error pages.
- `globals.css`: global `:focus-visible` ring and skip-link styles.
- `tsconfig.json`: `allowImportingTsExtensions` for native `node --test`
  type stripping (same pattern as `apps/team`).

Phase 0 inputs (positioning, offer hierarchy, proof inventory, sitemap) remain
founder-owned per decision 0002; the existing brand direction was assumed and
preserved.
